## Auto Increment란?

Auto Increment란, 데이터 베이스에서 새 레코드가 추가 될때마다 숫자 필드의 값을 1씩 자동 증가시키는 기능입니다.
주로 테이블의 PK를 설정할때 많이 사용됩니다. 이에 대한 장점으로는 다음과 같습니다.

첫째, DB가 알아서 값을 증가시켜 중복이 될 일이 없고 ID 생성을 위한 추가적인 로직을 구현 할 필요가 없습니다.<br/>
둘째, 보통 4바이트(INT)정도의 크기를 가져 차지하는 저장 공간도 적습니다.<br/>
셋째, 순차적이기 때문에 인덱스 성능 및 저장시 유리합니다.

Auto Increment의 단점은 뭘까요?<br/>

첫째, 이러한 정수형 ID + 1씩 증가하는 구조때문에 어느정도 추측이 가능하다는 취약점이 존재합니다. 외부에서 다른 데이터의 ID를 예측할 수 있고
또 새로운 데이터가 누적 될 때마다. 그동안 쌓인 데이터의 규모가 추정할 수 있어 보안적인 이슈가 발생할 수 있습니다.

둘째, 분산 데이터베이스 환경에서의 충돌을 고려해야합니다. 기본 Auto Increment를 그대로 사용한다면 서로 다른 데이터가 같은 ID를 갖게되어 데이터의 무결성이 깨질수 있습니다.

## UUID란?

UUID란, 범용 고유 식별자의 약자로 128-bit의 식별자입니다. 다른 고유 ID 생성과 다르게 중앙 서버가 필요가 없어서 더 
빠르고 간단하게 생성할 수 있습니다. 이를 PK에 적용했을때의 장점은 무엇이 있을까요?

첫째, 고유한 값을 보장하기 때문에 분산 데이터베이스 환경뿐만 아니라 다른 시스템 통합시에도 충돌 위험이 없습니다.<br/>
둘째, 예측하기 어렵기 떄문에 보안상으로 유리합니다.<br/>
셋째, 각 서버에서 독립적으로 생성할 수 있어 중앙 집중식 관리나 별도의 서버가 필요가 없습니다.<br/>

하지만 UUID에도 명확한 단점은 존재합니다.<br/>

첫째, UUID는 36자 문자열이기 때문에 Auto Increment에 비해 저장 공간을 더 많이 차지합니다.<br/>
둘째, UUID는 랜덤한 값이기 때문에 데이터가 많아지면 새 데이터 삽입시 데이터 정렬에 대한 오버헤드가 발생해 성능 저하가 발생할 수 있습니다.

## Auto Increment + UUID

또 다른 방안으로는 두가지를 적절히 혼용하는 방법도 있습니다.

```sql
CREATE TABLE entity (
  id INT AUTO_INCREMENT PRIMARY KEY,
  uuid VARCHAR(36) UNIQUE NOT NULL,
);
```
